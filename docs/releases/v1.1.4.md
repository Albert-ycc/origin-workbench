# Origin Workbench v1.1.4

Origin v1.1.4 upgrades the external model API setup experience from a command-oriented configuration page into a guided connection workflow. The release focuses on making OpenAI-compatible, relay, OpenRouter, and cc-switch setups understandable from the settings page while preserving the existing environment-variable path for advanced operators.

## Highlights

- The model API settings page now guides users through provider selection, API Key, Base URL, model ID, connection testing, and activation.
- Explanatory content moved into focused help dialogs and an advanced section, keeping the primary path centered on connecting a model service.
- Saved model API config now lives in a backend-local JSON file with file permissions set to `0600`; the UI only receives whether an API Key exists.
- Saving a model API config now runs a `/chat/completions` connection test first. Failed tests are not persisted.
- The standalone connection test returns diagnostics without silently writing the API Key or config file.
- Successful saves record the latest test result, latency, and best-effort `/models` discovery results.
- Tool root allowlists support `~`, `$HOME`, and `${HOME}` expansion, and are validated before saving.
- Self-hosted Docker now mounts a persistent backend config volume for saved model API settings.

## Compatibility Notes

- `ORIGIN_MODEL_*` and `OPENAI_*` environment variables still take precedence over the saved settings-page config.
- Services that do not support `/models` can still be saved when the `/chat/completions` connection test passes.
- The external model API runtime remains read-only for local tools: `list_directory`, `read_text_file`, and `search_text`.
- Shell, browser, MCP, and file-write capabilities still require a full local agent runtime.
